# CCVM 桌面端

App 的代码在 [`app/`](../app/)，开发见 [app/README.md](../app/README.md)。

## 状态

左下角和菜单栏只显示一件事：代理通不通。

| 状态 | 意思 |
|---|---|
| 已连接（绿） | VM 经代理出网，下面是出口 IP |
| 代理断开（红） | 17897 连不上代理，VM 已断网；代理恢复后自动变绿 |
| VM 已停止 / 还没部署（灰） | — |

出口 IP 变了不算问题，照常使用。状态变红时系统通知一次，同一个问题恢复前不再通知。会话不受状态影响，随时可以开、可以接回。

结论都来自脚本（`--json` 事件，见 [events.md](events.md)），在终端用 `bash scripts/check.sh` 能得到同样的结果。

## 网络

「网络」页：当前状态、各项检查、出网方式。

**自带核心**（推荐）：Homebrew 的 mihomo，App 以 LaunchAgent 运行，开机自动启动、意外退出自动拉起。

- 贴 Clash（YAML）订阅链接，选一个节点。链接只存钥匙串。
- 只有一个入口 `127.0.0.1:17897`，只收 TCP，固定走选定节点，其余拒绝。
- 每天自动更新订阅；节点的地址或密码变了会自动换上并重启核心。节点从订阅里消失时，核心继续用记下的节点信息。
- 测延迟时临时起一个没有入口的核心，测完即删。

**Clash Verge**：填节点名，复制扩展脚本，粘到订阅的「扩展脚本」里并重新激活订阅。

切换方式时 VM 会短暂断网。

## 项目与会话

- 首页列出 VM 里 `~/work` 下的项目；粘贴 Git 地址可以直接克隆（以 cc 身份）。
- 项目页左边是会话，右边是内嵌终端。会话跑在 VM 里 cc 的 tmux 中，关标签、窗口或 App 只是断开，Claude 继续运行。
- 外部终端（Terminal、iTerm、Ghostty）和命令行 `ccvm` 共用一份脚本：`ccvm` 进入 VM，`ccvm <项目>` 新建会话，`ccvm -a <会话>` 接回。
- Ghostty 需要 1.3.0 或更新，第一次会请求「自动化」权限。只用来开 VM 的 Ghostty 可以在配置里写 `command = ~/.local/bin/ccvm`。

## 文件

「文件」页以 cc 身份浏览 `/home/cc`：上传（选择或从 Finder 拖入）、新建、删除、下载。下载只支持单个普通文件。

## 共享文件夹（默认关闭）

设置 → 共享文件夹：把选定的 Mac 文件夹读写挂进 VM，在 `/home/cc/mac/<名字>`。每次应用都会重启 VM。

- VM（包括 Claude）可以修改这些文件夹里的任何文件，包括脚本和 `.git/hooks`。
- 不能共享系统目录、家目录本身、家目录下的隐藏目录、`~/Library`、`~/.ssh` 等，以及 CCVM 自己的目录。
- VM 里由 bindfs 映射，cc 看到的属主是 cc，新建的文件在 Mac 上属于你。

## VM 更新

早先部署的 VM 落后时，首页提示「更新 VM」：

| 级别 | 内容 |
|---|---|
| 1 | 安装 `git`、`tmux` |
| 2 | TUN 看门狗：系统更新重启网络服务后自动恢复 |

## 「Claude 做完了」提醒（可选）

设置 → 检查与提醒。在 VM 里由 root 装一个 Claude Code hook，只记录事件类型、时间和工作目录，不记录对话内容。同一项目 5 分钟内只提醒一次。
