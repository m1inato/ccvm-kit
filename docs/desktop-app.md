# CCVM 桌面端：工作方式与安全设计

App 的代码在 [`app/`](../app/)，用法见 [app/README.md](../app/README.md)。

## 原则

- **结论只来自脚本。** App 调用仓库里的脚本（`--json` 事件，见 [events.md](events.md)），自己不做安全判断。界面上的每个结论都能在终端用同一条命令复现。App 退出、崩溃或被卸载，VM 照样只能走专用入口。
- **不确定就当失败。** 脚本没跑完、输出读不懂、结论过期（超过 2.5 个检查间隔），都不显示成「受保护」。
- **出错时只拦新会话。** 正在运行的会话可以接回；新会话要等问题解决。
- **会断网、会改 VM 的操作先确认。** 切换出网方式、换节点、更新基线、应用共享文件夹、更新 VM，都先弹系统对话框。

## 出网

两种方式二选一，新装默认用自带核心。

**自带核心**（Homebrew 的 mihomo，App 以 LaunchAgent 运行）

- 只有一个入口 `127.0.0.1:17897`，只收 TCP，固定走选定节点；规则只有 `MATCH,REJECT`，不开局域网、虚拟网卡和 TCP 控制口。写入配置前反向核对一遍，不满足就不写。
- 绑定当前物理网卡；节点域名用这块网卡的 DHCP DNS 解析。网卡变了先停、改绑、再启动；没有物理网卡就保持停止。
- 每天更新订阅时逐字段比较选定节点：变了或消失就停核心、首页变红，等你确认或换节点。下载失败不动核心。
- 只支持 Clash YAML 订阅。订阅链接只存钥匙串；除选定节点外，其他节点只记名称、类型和服务器。
- 测延迟时临时起一个没有任何入口的核心，开统一延迟，测完即删。

**Clash Verge**：在它的订阅里加扩展脚本，生成专用入口 `cc-vm-in` 和策略组 `CC-VM-FIXED`。App 不改 Clash Verge 的配置。

换节点、重启或移除核心、切换出网方式之后，之前的检查结论作废，状态先变灰，等下一次检查。

## 连接面板

项目页「连接」列出来自 VM 的连接，并核对每条是否只经过选定节点。

- 自带核心：经本机 socket 直接读核心。
- Clash Verge：读它的外部控制器（需要在 Clash Verge 里打开并设密钥）。地址只能是本机回环；只允许 `GET /connections`、`/version`、`/proxies/CC-VM-FIXED`。密钥存钥匙串，不进设置文件、日志和导出记录。只看入站 `cc-vm-in` 的连接，链路必须正好是 `[节点, CC-VM-FIXED]`。
- 面板里的标红不改变首页状态：状态只由检查脚本决定。

## 会话与终端

- 会话跑在 VM 里 cc 的 tmux 中。关标签、窗口或 App 只是断开，Claude 继续运行。
- 新会话经 `enter.sh --session`：先做和外部终端一样的检查。接回已有会话经 `--attach`：不检查、不开新会话。
- 每个终端只属于打开它的窗口，写入和调整大小都核对归属。
- 外部终端（Terminal、iTerm、Ghostty）和命令行入口 `ccvm` 共用一份脚本：清代理变量，只带 CCVM 的设置和登录 shell 的 `PATH`，再调用 `enter.sh`。`ccvm <项目>` 新建的会话和内嵌终端开的一样出现在项目页。
- Ghostty 经 AppleScript 新开窗口（需要 1.3.0 或更新，第一次会请求「自动化」权限）。Ghostty 的 `TERM=xterm-ghostty` 在 VM 里没有定义，`enter.sh` 进 VM 前换成 `xterm-256color`。
- Ghostty 的配置不按窗口区分，新建标签的动作也不能带命令，所以做不到「只在 VM 窗口里按 Cmd+T 自动进 VM」。可以 Cmd+T 后输入 `ccvm`，或者在只用来开 VM 的 Ghostty 里配置 `command = ~/.local/bin/ccvm`。

## 共享文件夹（可选，默认关闭）

把你选定的 Mac 文件夹读写挂进 VM，VM 里在 `/home/cc/mac/<名字>`。**这会削弱隔离**，所以默认关闭，每次应用都要重启 VM 并确认。

**哪些变了**

- VM（包括 Claude）可以读写这些文件夹里的任何文件。
- VM 可以往里写脚本、改 `.git/hooks`、`package.json` 的 scripts、Makefile；你之后在 Mac 上运行它们，就是以你的权限执行。
- 这些文件夹的内容可以经固定出口发出去。

**哪些没变**

- 出网仍然只走选定节点；VM 仍然连不到 Mac 的网络服务。
- 不能共享：系统目录、家目录本身、家目录下的隐藏目录、`~/Library`、`~/.ssh`、`~/.gnupg`、`~/.aws`、`~/.config`、`~/.kube`、`~/.docker`，以及 Lima 目录、状态目录和套件目录。等于、在里面、包含都不行；按真实路径判断，符号链接绕不过去。

**怎么实现**

- 唯一来源是状态目录里的 `shares.txt`。`share.sh apply` 先检查路径，再停 VM、用 `limactl edit` 写挂载、启动并核对实际配置。Lima 全局配置（`_config/`）仍然一律拒绝。
- VM 里 Lima 挂在 `/mnt/ccvm-raw/<名字>`（cc 进不去），再用 bindfs 映射到 `/home/cc/mac/<名字>`：cc 看到的属主是 cc，新建的文件在 Mac 上属于你。
- 检查：实例的挂载集合必须正好等于 `shares.txt`；VM 里只允许这些名字的挂载，多出任何一个都变红。
- 「已应用」以 cc 看到的目录确实挂上为准；没挂上或上次应用失败时，可以重新应用。

## 文件

「文件」页以 cc 身份浏览 `/home/cc`：上传（选择或从 Finder 拖入）、新建、删除、下载。下载只支持单个普通文件，不跟符号链接。删除 `/home/cc/mac/` 下的内容会额外提醒：那是 Mac 上的真实文件。

## VM 更新

`setup.sh` 看到 VM 已安装就跳过网络层安装，所以早先部署的 VM 会缺后来加的东西。`guest/upgrade.sh` 按级别逐步补上，每完成一步记录级别；`setup.sh` 每次都会运行它，App 在 VM 落后时提示「更新 VM」。

| 级别 | 内容 |
|---|---|
| 1 | 安装 `git`、`tmux` |
| 2 | networkd 不再清理 sing-box 的策略路由（`ManageForeignRoutingPolicyRules=no`）；TUN 看门狗每 30 秒检查，路由丢了就重启 TUN |

第 2 级解决的问题：系统更新会重启 `systemd-networkd`，它默认清掉不是自己建的策略路由。TUN 进程还在运行，流量却进不了 TUN，VM 断网（防火墙还在，不会改走直连）。快速检查的 `vm.tun_routes` 能直接发现这种情况。

## 「Claude 做完了」提醒（可选）

在 VM 里由 root 写一个 Claude Code hook（`/etc/claude-code/managed-settings.d/50-ccvm.json`），cc 改不了，App 也不碰 `~/.claude`。hook 只记录事件类型、时间、工作目录和截断的通知文字，永远不影响 Claude。事件文件 cc 可以写，所以内容按不可信处理，只当文字显示。

## 不提供的功能

**VS Code 远程。** 远程连接在 VM 和 Mac 之间打开的通道不止端口转发：VM 里的扩展可以读写 Mac 的剪贴板、让 Mac 打开链接，远程终端里的 `git` 可以借用 Mac 上的 Git 认证。Claude 能在 VM 里装扩展，这些通道在设置里关不干净，所以不提供一键连接。代码只走 Git：在 VM 里推分支，回到 Mac 上审看。

**在 Mac 上执行命令（例如 `xcodebuild test`）。** 被执行的代码来自 VM，而 Mac 上的执行账户网络不受限，可以绕过固定节点直接出网，也能连到 Mac 本机的代理端口。在找到能可靠限制它的办法（按用户过滤的 pf 规则或沙盒）之前，不提供这个功能。
